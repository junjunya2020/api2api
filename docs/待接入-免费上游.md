## 五、接入新渠道的标准动作（零改代码优先）

> ⭐ **2026-10-08 起：加渠道只需改 api2api，qq 桥会自动跟随**（见下方第 7 条）。

1. **优先用通用适配器 `openai_compat`** —— 若上游是标准 OpenAI 兼容 + 标准 `{error:{message,code}}` 壳，
   **无需写适配器**，只加渠道即可。
2. 在 `src/db/schema.mjs` 的 `BUILTIN_CHANNELS` 加一条：`name / display_name / adapter / base_url / sort_order / note`。
   - `sort_order` 越小优先级越高；**兜底渠道放到最大**（如 50+）。
   - ⭐ `display_name` 会被 api2api `/api/channels` 下发，桥**直接用它**做展示名（桥无需改）。
3. 只有上游错误壳**非标准**时才写专属适配器（参考 `nvidia.mjs` 顶层壳、`sensenova.mjs` gRPC 壳、
   `llm7.mjs` 的 402 语义）。
4. 加 Key：`POST /api/keys`（渠道名 + Key）。
5. 拉目录：`POST /api/models/fetch` `{channel}`。
   - 若目录**严重虚胖**（大量挂死/退役），把它加进 `src/db/fast-models.mjs` 的 `FAST_ONLY_CHANNELS`
     并给出实测白名单 → 默认「只接快速模型」会过滤。
6. 跑测试：`smoke` / `e2e` / `migrate` 全绿（加渠道会改内置渠道数断言，记得同步）。
7. **互助计划（桥侧）—— 无需改动**：
   - **展示**：桥的渠道列表实时拉 api2api `/api/channels`，展示名取其中的 `displayName`。
   - **奖励**：桥对**未显式配置**的渠道自动用 `A2A_REWARD_DEFAULT`（默认 `1,3` 美元），
     并把 api2api 实际渠道并进奖励展示 → 新渠道**自动参与互助奖励**。
   - 想给某渠道**自定义**区间：改 env `A2A_REWARD_EXTRA="chan:2,8"` 即可，**不用改代码**。
   - 想**关闭**自动发奖（回到必须显式白名单）：`A2A_REWARD_DEFAULT=""`。

> ⚠️ 教训（2026-10-08）：新增内置渠道后，e2e 的「未拉过目录的渠道不会被误跳过」用例曾失败 ——
> 一个**没配任何 Key** 的渠道会赖在候选里（它是"未知 ≠ 没有"），使兜底失效 → 请求被凭空 503。
> 已修：relay 预先剔除 `enabledKeyCount == 0` 的渠道。
